# 持续产出、平衡配置、AI 内容与发布整理设计

日期：2026-08-13

## 1. 目标与范围

本轮按五个阶段完成：

1. 修正建筑产出的单位表达，并统一每日结算与界面显示所用的计算逻辑。
2. 扩展产品、游客、和平考察、居民日记和年度评语五类 AI 文案。
3. 增加科技完成、新 biome 解锁、首次发现组合、外交声望阶段和资源长期短缺五类自然触发。
4. 建立正式的 Node 逻辑测试、统一验证命令和部署前检查。
5. 整理 README、平衡教程、设置说明、遗留字段与发布配置，并在验证后提交和推送到 GitHub。

本轮不包含默认像素纹理包、大量新增静态建筑或种族、游戏内平衡编辑器、战斗、居民行为深化或架构重写。

## 2. 设计原则

- 核心玩法事实和数值由本地确定性代码决定。
- AI 只能命名、描述、评价和建议，不能决定成本、产出、路线、品质、奖励、解锁或概率。
- 网络、模型或额度不可用时，所有相关功能必须通过本地 fallback 正常运行。
- 新状态必须可 JSON 序列化，并在读取缺少这些字段的存档时补默认值。
- 复用现有 `GameState`、`EventBus`、`AIClient` 和各系统边界，不建立通用 DSL 或大型内容引擎。
- 静态内容提供最低完整玩法；AI 用于增加变化，不是唯一内容来源。

## 3. 建筑持续产出与平衡配置

### 3.1 当前行为与修正目标

建筑当前已在每个游戏日持续结算，而非建成时一次性发放。现有问题是界面只显示类似“金属 +4”的基准效果，既没有时间单位，也不等于经过基础倍率和各种加成后的实际日产量。

本轮保持逐日结算，统一显示 `/天`，并消除每日结算与 UI 各自复制公式的问题。

### 3.2 统一计算边界

新增集中平衡配置模块以及可复用的建筑产出计算函数：

- 建筑定义继续保存基准效果，例如采矿站的 `metal: 4`。
- 平衡配置保存建筑基础产出倍率等全局参数。
- 计算函数接收建筑定义、建筑实例和明确的上下文，返回各资源的每日产量。
- 每日资源结算与设施管理面板调用同一函数。
- 建造面板调用同一函数的“基准上下文”，显示未计入选址后实例加成的基础日产量。

实际日产量可包含：

- 建筑基础产出倍率；
- 建筑等级；
- 道路连通与运行状态；
- 居民工程、农业或科研技能；
- 季节倍率；
- 农业、科研或全局效率加成；
- 已激活建筑组合。

停运建筑返回零日产量，并保留停运原因。所有资源增加仍通过 `GameState.addResource` 执行。

### 3.3 UI 表达

资源管理界面同时显示每日总产出、持续消耗和净变化，帮助玩家判断储备趋势：

- `食物：产出 +3.2/天 · 消耗 -0.9/天 · 净增 +2.3/天`
- `能源：产出 +4.5/天 · 消耗 -1.0/天 · 净增 +3.5/天`
- 没有持续消耗的资源可省略消费项，但仍显示净变化。

人口口粮以及当前或未来建筑维护等持续消耗必须进入统一资源流量计算，不能只在每日结算中暗扣。生产配方在订单开始时一次扣除的原料继续显示为“本次消耗”，不得标记为 `/天`。资源流量显示应区分规则计算值与因存储已满、资源见底而实际截断的变化，避免玩家误判生产能力。

建造面板显示基准值：

- `基础产出：金属 +0.6/天`
- `基础产出：食物 +0.9/天`

设施管理面板显示当前实例值：

- `当前产出：金属 +0.83/天`
- 停运时：`当前产出：金属 +0/天 · 未连接降落点`

效果分类如下：

- 资源流量：显示 `/天`。
- 人口、存储等容量：显示 `人口上限 +4`、`存储上限 +100`，不加 `/天`。
- 旅游、幸福度、防御等持续属性：明确写作“运行时提供”或“持续影响”，不伪装成一次性资源奖励。
- 解锁类效果：使用“解锁贸易”等描述。

格式化结果避免不必要的长小数，并允许小于 1 的产量清晰显示。

### 3.4 集中平衡文件与教程

集中平衡配置至少覆盖：

- 建筑基础产出倍率；
- 人口每日食物消耗；
- 建造速度；
- 加工时长倍率；
- 居民经验和成长速度；
- 游客预算、消费倍率与到访间隔；
- 随机事件频率；
- AI 提案间隔；
- 资源短缺阈值、持续天数和冷却。

新增 `docs/BALANCING.md`，用中文说明每个字段的单位、推荐范围、修改示例、恢复方式，以及修改后应运行的验证命令。平衡配置不进入玩家存档，也不提供游戏内编辑器。

## 4. AI 与静态内容的边界

AI 已能提出建筑、组合和外星种族，因此本轮不再把大量同类静态内容扩充作为独立目标。固定的基础建筑、区域、配方、种族和 fallback 仍保留，以确保离线可玩和核心进度稳定。

统一数据流为：

```text
本地系统确定事实和数值
        ↓
AI 根据事实生成文案
        ↓
本地校验格式、长度和和平主题边界
        ↓
有效则显示 AI 文案，否则立即使用 fallback
```

生成建筑和组合仍经过现有本地白名单、预算和引用校验。AI 返回值不能直接写入核心数值状态。

## 5. 五类 AI 内容

### 5.1 产品命名与描述

加工配方、输入、输出数量、时长、品质和用途由本地数据决定。AI 根据这些事实生成产品显示别名和描述。

- 产品固定 `id` 不变；库存和配方始终引用固定 `id`。
- AI 名称仅作为展示别名，不允许改变配方或数值。
- 可按产品和品质档缓存文案，减少重复请求。
- 无 AI 时使用现有静态名称和描述。

本轮不允许 AI 创建任意新配方。

### 5.2 游客个性与评价

游客创建时，本地系统先确定种族、个体偏好、预算、路线、满意度、访问地点和消费。AI 只生成：

- 简短个性标签；
- 到达时的一句话；
- 基于真实路线和满意度的离开评价。

AI 文案不得修改游客路线、预算、消费、满意度或外交奖励。请求失败或返回较晚时，不得阻塞游客到达、移动和离开结算；界面使用本地模板并可在异步结果返回后更新附加文案。

### 5.3 和平考察记录

本地系统继续决定区域、技能要求、补给、天数、奖励、biome 解锁和居民经验。AI 只生成：

- 出发记录；
- 途中观察；
- 完成报告。

内容不得加入战斗、永久死亡、伤害、建筑摧毁或惩罚性失败。若以后展示途中变化，也只能引用本地预设、可恢复且不改变核心奖励表的轻量事实；本轮不新增由 AI 决定的随机分支。

### 5.4 居民事实型日记

日记请求使用结构化近期事实，例如：

- 建筑完成；
- 居民等级或技能成长；
- 参与加工；
- 完成考察；
- 当前季节和心情；
- 资源短缺或恢复。

AI 只能改写传入事实，不得虚构不存在的建筑、居民、事件或关系。fallback 使用同一事实对象。日记上下文应可独立测试，确保只包含当前状态中已发生的事实。

### 5.5 年度评语

`AnnualReviewSystem` 继续确定六维分数、平均分、等级、奖项、排名和事实摘要。AI 只根据已确定报告生成：

- 年度总结；
- 最强维度说明；
- 一个温和的下一年建议。

AI 不得修改任何评分、等级、奖项、排名或奖励，也不得使用惩罚性排名措辞。离线时根据强项、弱项和发展阶段组合本地评语。

## 6. 五类自然触发

### 6.1 状态与通用限制

扩展 `aiContent` 的可序列化状态，保存：

- 已处理科技或其他里程碑；
- 已处理 biome；
- 已处理组合；
- 各资源短缺持续天数；
- 各触发类型最后发生日。

加载缺少这些字段的存档时补空集合或默认计数。

通用限制：

- 待确认提案最多 3 个；
- 同类触发有独立冷却；
- 同一里程碑只处理一次；
- AI 关闭时不创建或积压请求；
- 重新打开后不补发全部历史事件，只响应新事件和低频兜底；
- 现有按天数生成提案保留为低频兜底，但事件触发优先。

### 6.2 科技完成

科技研究完成时发出明确事件，并按科技类别请求相关内容候选。农业、文化、加工和外交等科技分别倾向对应建筑、产品文案或交流内容。生成的玩法内容仍进入待确认列表，不能自动接受。

### 6.3 新 biome 解锁

监听地图揭示事件。雪地和沙漠等 biome 首次解锁后，可生成与环境匹配的建筑或产品叙事。提示上下文只包含已经解锁的区域；每种 biome 只触发一次。

### 6.4 首次发现组合

首次发现组合时立即生成组合评价；冷却允许时可额外生成新组合提案。同一组合不会重复触发，AI 关闭或失败不影响组合本身生效。

### 6.5 外交声望阶段

复用现有外交阶段事件。达到种族里程碑时生成对应交流文本；较高阶段可提出种族或文化内容。实际阶段奖励仍完全由本地代码发放。

### 6.6 资源长期短缺

每日确定性检测食物、能源、金属等资源：

- 低于配置阈值时累计短缺天数；
- 恢复到阈值以上时清零；
- 达到配置的持续天数后才触发；
- 每种资源使用独立冷却，避免重复打扰；
- 优先生成顾问建议，待确认列表有空间且冷却允许时才考虑对应建筑提案。

AI 不能直接增加资源、改变产出或自动建造。

## 7. AI 请求、校验与错误处理

在现有请求体系中增加请求类型、输入事实、长度限制、JSON schema、缓存策略和本地 fallback，不建立第二套客户端。

处理顺序：

1. 在线配置不可用时直接 fallback；
2. 网络超时或请求失败时 fallback；
3. 连续失败达到限制后，本会话继续使用 fallback；
4. JSON 解析失败时 fallback；
5. 响应违反 schema、长度或和平主题边界时拒绝并 fallback；
6. AI 请求不得阻塞每日 tick、生产完成、游客离开、考察完成或年度结算。

API 密钥仍只允许留在当前标签页会话中，不进入 localStorage、游戏存档、`VITE_*` 环境变量或构建产物。

## 8. 自动化测试与验证命令

使用 Node 内置测试运行器，避免增加第三方测试框架。增加：

```text
npm test
npm run test:watch
npm run verify
```

`npm run verify` 按顺序运行：

1. 正式逻辑测试；
2. 架构索引校验；
3. Vite 构建。

### 8.1 建筑与平衡测试

- 建筑逐日持续产出并可跨多天累计；
- 停运建筑不产出；
- 等级、技能、季节和组合加成正确；
- 每日结算与 UI 使用同一产量结果；
- 容量和解锁效果不会错误标注 `/天`；
- 持续产出、持续消耗和净变化使用同一资源流量结果，人口口粮计入消耗；
- 一次性配方原料不会被错误归入每日消耗；
- 集中配置改变后，对应系统结果随之变化。

### 8.2 AI 边界测试

- 产品文案不能修改产品 ID、配方或品质；
- 游客评价只读取既定路线、访问和满意度；
- 考察叙事不能修改奖励；
- 居民日记上下文来自已发生事实；
- 年度评语不能修改评分；
- 无在线配置时所有新类型都有 fallback；
- 非法、越界或禁用主题响应被拒绝。

### 8.3 触发测试

- 科技、biome、组合和外交里程碑只触发一次；
- 资源短缺必须持续达到配置天数；
- 资源恢复后计数清零；
- 冷却和待确认上限有效；
- 存档读取后旧里程碑不会重复触发；
- AI 关闭时不生成请求，重新打开时不补发历史事件。

### 8.4 教程测试

- 基础教程步骤按顺序推进，等待事件只推进一次；
- 跳过、完成和异常退出均恢复进入教程前的游戏速度；
- 高亮目标缺失或目标事件已经发生时可手动继续；
- 各上下文提示只显示一次，重置全部教学提示后可再次显示；
- “重新开始基础教程”不清除上下文提示状态；
- AI 离线时教程完整可用；
- 资源教学文案正确区分日产出、持续消耗、净变化和一次性配方消耗。

## 9. 发布整理

本轮完成：

- 扩展新手教程，采用“短主线＋按首次解锁出现的上下文提示”：基础主线介绍暂停、资源日产出/持续消耗/净变化、建造、道路、设施实际日产量和居民；上下文提示介绍加工、升级、组合、科研、和平考察、游客、外交、AI 提案、年度总结和长期短缺；
- 教程和每条上下文提示均可跳过且不依赖在线 AI；教程开始时保存速度并暂停，结束后恢复；目标缺失、面板提前关闭或目标事件已经发生时必须允许手动继续，不能卡死；
- 设置页保留“重新开始基础教程”，并增加“重置全部教学提示”；基础完成状态和上下文提示已读状态保存在本地教程偏好中，不改变玩法数值，也不随存档导入覆盖；
- README：游戏简介、启动、构建、测试、存档导入导出、自定义纹理、玩家 AI 配置和安全注意事项；
- `docs/BALANCING.md` 平衡调整教程；
- 设置页分区与说明文字整理，但不重做整体视觉设计；
- 审查遗留战斗字段与注释，只移除确认无调用且不承担兼容职责的内容；
- 压缩 `npm run context -- <system-id>` 的默认上下文包：默认不再整份嵌入 `CLAUDE.md`、`SYSTEMS.md` 和全部源码，而是输出系统契约、状态所有权、事件、关键导出、目标文件清单和受控源码片段；默认字符预算显著低于当前 120000 字符，并提供显式参数按需展开完整文件或提高预算；
- 为上下文生成器增加测试，校验默认包不会超出预算、不会重复嵌入全局文档、仍能定位目标源码与直接调用方，适合约 200k 上下文模型先定位后精读；
- GitHub Pages 工作流在部署前运行 `npm run verify`，失败则不部署；
- 检查 Vercel 配置和单文件构建输出；
- 在浏览器中验收日产量、持续结算、AI fallback 与自动触发、产品文案、游客评价、考察记录、居民日记、年度评语、设置和存档流程。

实现和验证通过后，将本轮改动提交并推送到 GitHub。推送属于最终交付步骤；若远端拒绝、鉴权失败或出现非快进冲突，应保留本地提交并如实报告，不强制覆盖远端历史。

## 10. 实施顺序与完成标准

### 阶段一：持续产出与平衡

- 集中配置可被相关系统引用；
- 每日结算和 UI 共用产量计算；
- 建造页显示基准 `/天`，设施页显示当前 `/天`；
- 平衡教程完成；
- 对应测试和构建通过。

### 阶段二：五类 AI 内容

- 五类内容都拥有结构化事实、校验和 fallback；
- AI 不改变本地玩法结果；
- 对应测试通过。

### 阶段三：五类 AI 触发

- 事件驱动触发、防重复、冷却、短缺累计和存档默认值完成；
- 历史事件不补发；
- 对应测试通过。

### 阶段四：正式测试

- `npm test`、`npm run architecture:check` 和 `npm run build` 整合为 `npm run verify`；
- 测试覆盖本设计列出的关键边界。

### 阶段五：发布整理与交付

- 扩展基础教程和解锁式上下文提示，并通过推进、恢复速度、防卡死和一次性显示测试；
- README、设置说明、遗留项审查、CI 与部署配置完成；
- 默认系统上下文包从整文件拼接改为小型定位包，并通过预算与定位能力测试；
- 浏览器关键流程验收完成；
- `npm run verify` 最终通过；
- 改动提交并推送到 GitHub，且不使用强制推送覆盖远端历史。
